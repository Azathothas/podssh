# Decisions

This page lists the decisions of the operator (the owner of the project).
The newest decision is first in each section.

- Do not change a decision without the operator.
- When a decision changes, edit its row and move the old text to
  "Superseded". Do not keep two versions as current.

A session works until the operator interrupts it, or until each entry of `TODO/` is done except the entries that wait for the relay's operator (T-086, T-106, T-169, T-173, T-180, T-226, and each later entry that needs a change of the relay), each test passes, and `v1.0.0` is published and verified from end to end. | 2026-10-08 | **`podssh pipe exec:CMD` is allowed** (Q22; T-174). The user names the program, as with `SSH_ASKPASS`; the rule against helper processes is about podssh's own shims. |

The blocking facade of `podssh-relay` for podbox is built and tested in this repository (T-081), with Rust 1.88 if it needs that; podbox follows. Pinning it in podbox is an operator action after the release: no session changes another repository (T-085). |
| 2026-10-08 | **A tty that podssh makes where `/dev/ptmx` is missing** (Q11; T-248). Two routes, each after a probe at run time: a new devpts instance in a user namespace, which is a real pty (the operator: the boxes have no user namespaces), and a tty in user space: `podssh serve` answers its own child's tty system calls (seccomp user notification, or ptrace). The second is not a shim: it puts no code into the child, and it works with static binaries. `LD_PRELOAD` stays forbidden. The exit criterion of M5 keeps `vi`, `less` and Ctrl-C. |
| 2026-10-08 | **A local listener when the user asks for it and a probe allows it** (Q1). `-L` and `-D` (T-038), connection sharing (T-039), `serve --listen` (T-124), a local session daemon (T-186) and `podssh agent` (T-034) may listen when the user asks for them and a probe at run time shows that the bind works. The default address is loopback, or an AF_UNIX socket. The user can set the address, and can turn listening off. Where the probe fails, podssh refuses with a clear message, as now. Nothing listens until those entries are done. |
| 2026-10-08 | **Three ways to try the relay hosts** (Q10; T-220, GitHub #30), selected by a flag: a staggered start (the default: the next host starts when the first has not opened within a short delay), all hosts at once, or one host at a time with a shorter connect limit for a host that has a successor. The first success in the order of preference wins, and the other attempts close at once. So podssh can have more than one outbound connection for a short time; the session uses one. |
| 2026-10-08 | **Agent forwarding (`-A`) is in the scope of podssh** (Q2; T-036), off by default as in OpenSSH. |
| 2026-10-08 | **The SSH agent and the credential helper are parts of podssh** (Q5), not separate binaries: `podssh agent` (T-034), a credential helper (T-228), and hardware keys (T-229). |
| 2026-10-08 | **No road depends on a program of another project** (Q3: `cloudflared`, `mosh-server`). podssh makes their useful functions itself where that makes sense: a Cloudflare quick tunnel, which trycloudflare.com makes scriptable (T-170), and the functions of Mosh that M6 and T-160 do not give (T-171). |
| 2026-10-08 | **The relay stays a separate project** (Q4, Q9). Its contract is the boundary of podssh. A self-hosted relay (T-169), an endpoint that publishes a local HTTP service (T-180), and signed pairing grants that are used once (T-226, GitHub #35) wait for the relay's operator. M4 keeps the relay's tokens, in a header or a 0600 file and never in a URL; the trust is end to end: the host key of the node and the allowlist of keys (T-087, T-107). |
| 2026-10-08 | **podssh is a CLI** (Q6). No GUI, no TUI, no emoji. The requests for a menu-bar app and for colored command blocks (reports in GitHub #24 and #25) are closed by this ruling, with no entry. The triage of an error by an AI is a hook of the CLI: podssh gives its report to a program that the user names (T-195). |
| 2026-10-08 | **Devices and workloads are streams** (Q7). A `serial:` address for `podssh pipe` (T-181); USB/IP as a tested recipe over `podssh pipe`, with no driver in podssh (T-182); a queue of detached remote jobs, with no GPU logic (T-197). |
| 2026-10-08 | **The surface for agents comes after the beta and before M4** (Q8): T-049, T-050, T-012, T-052 and T-051 (GitHub #9 to #13). |
| 2026-10-08 | **The way to a finished podssh** ([design.md](design.md)). The first beta waits for milestone M3: relay failover, liveness, a fallback for no proxy and no DNS, `doctor`, `keygen`, and a run in a real sandbox. Then M4 (`podssh-relay`, the reverse road, podbox), M5 (`podssh serve`), and M6 (sessions that survive a drop). M6 builds two resumable layers, each the fallback of the other: podssh's own layer over the WebSocket relay, and iroh. |
| 2026-10-08 | **iroh is a road that the user must select**, for connections between two podssh binaries. Its relays are configurable. The default is n0's public relays until the operator runs an iroh relay on the operator's own Cloudflare account. Then the operator's relay is first and n0's relays are the fallback. |
| 2026-10-08 | **The SSH client is `russh` with the `aws-lc-rs` backend, in the default build.** The rule "no C" applies to the library crates only: `podssh-ws`, `podssh-relay`, `podssh-transport`, `podssh-core`, `podssh-terminal`, `podssh-probe`. The `podssh` binary links aws-lc. |
| 2026-10-08 | **The repository is public.** The git history was replaced by one commit (the old history is in a local bundle), and the old CI runs were deleted. Verified milestones are pushed without a question. `v0.1.0-beta.1` is tagged and released, with static Linux binaries and checksums, when M3 is complete. |
| 2026-10-08 | **Milestone 1 gives a usable default.** The relay `tcp.ssh.relay.ajam.dev` is compiled in, and the user can override it. Mozilla's root store (`webpki-roots`) is the last trust fallback, after an explicit CA file and the system bundle. |
| 2026-10-08 | **Tailscale is a feature that the user must select.** `podssh ts` is the `ts` cargo feature, because the fork uses most of the build time, the memory and the binary size. |
| 2026-10-05 | **Do not assume that the client has a privilege, a tool or a setup.** The operator's words: *"NEVER ASSUME OUR CLIENT HAS ANY PRIVS, TOOLS, SETUP."* podssh probes what the host gives at runtime. What a host gives changes between sessions and images. |
| 2026-10-05 | **Tailscale support** (`podssh ts`, alias `tailscale`). "Vanilla" means a TUN device. The automatic chain is tun, then socks, then tcp, then relay. `podssh ssh` does not use the tailnet automatically in the first release. A wait for the relay's allowlist is used only on request; the default is to fail fast. A client-side DERP home pin is in the fork. |
| 2026-10-05 | **Exit codes:** 64 for a usage error, 78 for a configuration error (sysexits). |
| 2026-10-04 | **IRC safety:** podssh never executes something that it receives over chat, and never gets a peer's files on its own. |
| 2026-10-01 | **No `LD_PRELOAD`, and no shims in other processes.** A preload shim fails silently against a static binary and looks like an authentication failure. podssh supplies in its own process what the host does not have. |
| 2026-10-01 | **The terminal must be usable after the connection.** When no part gives echo, editing and history (no pty on either side, and no line discipline on the server), podssh supplies the line discipline. A server with no pty can have its own line discipline (podbox has one), so three inputs select the mode. See [terminal.md](terminal.md). |
| 2026-10-01 | **IRC is necessary.** Two users in constrained hosts must be able to chat and share files. podssh supplies the protocol and the relay carries the bytes, as for SSH. Open items: the client sends plain text to public IRC servers, and the topology with no third-party server has no design yet. |
| 2026-10-01, 2026-10-08 | **Tokens** (Q12 and T-057 on 2026-10-08): one machine has one cached token for each relay deployment. The hosts of one deployment share it, and podssh never sends a token to a deployment that did not mint it (T-057). The cache is in the first usable directory of: a directory that the user names (T-243), the user's cache directory, the user's runtime directory, the temporary directory, the working directory. The temporary directory is `TMPDIR`; when it is not set, podssh resolves one at run time, and only then tries the fixed fallbacks (`/tmp`, `/dev/shm`). podssh probes each directory, and skips one that does not exist or refuses a write. The mode is 0600. If `chmod` fails, podssh continues. |
| 2026-10-01 | **Command line:** `podssh` with no subcommand never connects. `chat` is the IRC subcommand. The code generates the man page. |
