# podssh v1.0.0-beta.2

The second beta. It carries the repairs since `v1.0.0-beta.1` and more
platforms, and it is the first release that proves where each binary comes
from. A beta is a prerelease. Its tag never moves: a defect found in it goes
into the next beta.

## The files

| File | For |
| --- | --- |
| `podssh-x86_64-unknown-linux-musl` | Linux on x86-64, static: no library and no loader needed |
| `podssh-aarch64-unknown-linux-musl` | Linux on aarch64, static |
| `podssh-armv7-unknown-linux-musleabihf` | Linux on 32-bit ARM with hard float (a Raspberry Pi with a 32-bit system), static |
| `podssh-riscv64gc-unknown-linux-musl` | Linux on 64-bit RISC-V, static |
| `podssh-aarch64-apple-darwin` | macOS on Apple silicon; it links the system's libraries only |
| `podssh-x86_64-apple-darwin` | macOS on Intel |
| `podssh-x86_64-pc-windows-msvc.exe` | Windows on x86-64, with a static C runtime |
| `podssh-aarch64-pc-windows-msvc.exe` | Windows on ARM64, with a static C runtime |
| `SHA256SUMS` | The SHA-256 of each binary |
| `SHA256SUMS.sigstore.json` | The signature of `SHA256SUMS`: Sigstore's keyless signing, by the release workflow at this tag |
| `provenance.sigstore.json` | The provenance of each binary (SLSA), signed the same way: the workflow, the tag and its commit |
| `THIRD-PARTY-LICENSES.md` | The licenses of the crates in the binaries, with their texts |

Each binary ran on its own platform before it was published: `--version`,
the whole manual, `keygen` and `keygen -y`, and GitHub's SSH banner through
the live relay.

## Check a download

```sh
T=v1.0.0-beta.2; B=podssh-x86_64-unknown-linux-musl   # or another file of the table
curl -fsSLO "https://github.com/Azathothas/podssh/releases/download/$T/$B"
curl -fsSLO "https://github.com/Azathothas/podssh/releases/download/$T/SHA256SUMS"
grep " $B\$" SHA256SUMS | sha256sum -c - && chmod +x "$B"
./"$B" --version   # podssh 1.0.0-beta.2 (the commit of the tag)
./"$B" doctor      # what this host allows, and whether the whole path works
```

On macOS, check with `shasum -a 256 -c` in place of `sha256sum -c -`. A
binary that `curl` fetched has no quarantine; after a browser's download,
run `xattr -d com.apple.quarantine "$B"` first. On Windows, compare
`(Get-FileHash podssh-x86_64-pc-windows-msvc.exe).Hash` with its line in
`SHA256SUMS` (the case of the letters differs).

The provenance of a binary names the release workflow and the tag (with the
GitHub CLI):

```sh
gh attestation verify "$B" --repo Azathothas/podssh \
  --signer-workflow Azathothas/podssh/.github/workflows/release.yml --source-ref "refs/tags/$T"
```

The signature of `SHA256SUMS` names the workflow at the tag (with cosign; 3.x
and 2.6 both check it):

```sh
curl -fsSLO "https://github.com/Azathothas/podssh/releases/download/$T/SHA256SUMS.sigstore.json"
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Azathothas/podssh/.github/workflows/release.yml@refs/tags/$T" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
```

The two proofs and `podssh --version` name the same commit.

## What works

`podssh ssh`, `each`, `run`, `job`, `session`, `containers`, `proxy`, `pipe`,
`cp`, `mv`, `scp`, `sftp` and `edit`, `doctor`, `keygen`, `agent`, `man`,
`status`, `ping`,
`health`, `node`, `operator`, `relay`, `chat`, `play` and `config`, and
`mcp`. `podssh man` is the reference: each command, flag, `-o` keyword,
variable, file and exit code. These binaries have no Tailscale and no iroh
road: `podssh ts`, and a destination `iroh:TICKET` or `--iroh-ticket`, exit
with 70 and say so.

## What to test again

New since `v1.0.0-beta.1`:

- `podssh doctor` tells apart three failures of the WebSocket upgrade, and
  measures each TCP probe nine times, with its loss (#54, T-324). It names a
  proxy that answers `200` to CONNECT and then carries no SSH (T-317).
- A proxy that answers `407` is named with what it asks for; podssh sends
  Basic from the user and password of the proxy URL (T-320).
- A relay's name pinned to a loopback address goes with no proxy (T-318).
- Each frame of a forward is 32 KiB at most, the relay's own limit (T-323).
- `podssh each --interactive --stop-key ^X`: the stop of a broadcast on a
  key that you choose (T-322).
- `podssh node --install` and `--uninstall`: the node as a service of its
  user, with no privilege (T-121).
- `podssh config import putty|mobaxterm|remmina FILE`: hosts from the
  sessions of those programs (T-292).
- `podssh agent` on macOS: its socket goes under `/tmp` where the temporary
  directory's path is too long for a socket (T-034).
- `podssh session start NAME HOST`, then `send`, `wait`, `capture` and
  `stop`: a session with a pty that a podssh of its own keeps in the
  background, for a program that drives a terminal (T-186).
- `podssh job start|list|log|stop HOST`: jobs in the far host's tmux that
  go on after the connection ends (T-193); and its queue, `submit` with
  `--slots`, `wait` and `fetch`, and a submit to a list of hosts that goes
  to the one with the fewest jobs (T-197).
- `podssh run HOST -- COMMAND`: the project goes to the host, only the files
  that changed, and the command runs in it with its exit status (T-192).
- `podssh node --resume-deadline TIME`: a node keeps a lost session up to
  72 h, and names the time to its clients (T-306).
- With the resumable layer of a node: a notice in the window's title while
  the node is silent, which counts up and leaves the screen as it was
  (T-302); and a spare link beside a link that went silent, so that a new
  address of this host costs seconds, not 30 s (T-305;
  `PODSSH_SPARE_LINKS=no` turns it off).
- The new platforms of the table: macOS, Windows on ARM64, and Linux on
  32-bit ARM and on RISC-V.

## What a beta does not have yet

- The check of a release from end to end with no human (T-251); it runs
  before `v1.0.0`.
- Signatures of the platforms: the Mac binaries are not signed with an
  Apple Developer ID, and the Windows binaries carry no Authenticode
  signature, so SmartScreen may warn. The proofs above stand in for them.

## Report a defect

Open an issue at <https://github.com/Azathothas/podssh/issues> with the
output of `podssh --version` and `podssh doctor --json`. Read that output
before you post it: it names this host's proxy and addresses, and never a
token or a password.
