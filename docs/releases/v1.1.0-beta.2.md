# podssh v1.1.0-beta.2

The second beta of milestone M10: the relay as a role of podssh itself
(`podssh relay serve`) and the net of a user's own nodes grow by many
parts, and the default list of relay hosts takes a rank that this host
measured. A beta is a prerelease. Its tag never moves: a defect found in it
goes into the next beta.

## What to test again

The relay role, `podssh relay serve`:

- A proxy that refuses the WebSocket upgrade: the HTTP road carries the
  session in plain requests, where a probe found the upgrade refused
  (T-319, its first part; Q44).
- HTTP/2: a host's sessions of one process are streams of one TLS
  connection, the WebSocket over extended CONNECT (RFC 8441), with
  HTTP/1.1's upgrade where the server does not offer it; `PODSSH_H2`
  chooses, `doctor` names the ALPN (T-321, its first part).
- A cleartext road on port 443, tried after the TLS road fails (T-326).
- A standard sshd's session across a drop of the client's link: `podssh
  proxy` and `podssh ssh` take the role's road in the resumable layer where
  the first host offers it, its offer kept for a day; `PODSSH_RELAY_LAYER=yes`
  reads the offer at each run and says each case, `no` turns the road off;
  `--resume-budget`, `--resume-deadline` and `--resume-host` bound and name
  it (T-173).
- A connect token for each leg of a session, and a stop token that the node
  rotates (T-615); a pair that its owner renews in the role (T-592).
- A planned stop that no session feels (T-255); a bound on what waits for a
  slow reader (T-336); the role's dials through the host's `HTTPS_PROXY`
  (T-457); its mint for the members of the net (T-455); its IPv6 targets,
  and `doctor`'s line `ipv6` (T-253).
- Relay hosts outside the default domain from a list of deployments that a
  trusted key signs (T-346).
- `podssh doctor --stream`: what the path does to a stream (T-325).

The net and its nodes:

- `podssh net invite` and `podssh net join`: a new device joins the net by
  a short code (T-616); pairing by a short one-time code given out of band
  (T-086); grants that are signed and used once (T-226, GitHub #35).
- Routes: a node reaches its private networks for the net, `--exit auto`
  picks the exit whose routes hold the target, and an exit never dials its
  own addresses (T-432).
- `ssh`, `proxy` and `pipe` take `--exit` beside `--carrier` (T-614,
  GitHub #124), the exit over a carrier (T-596), and `podssh doctor --exit
  NAME` (T-458).
- `--no-resume`, a session to a node that ends with its link (T-612);
  `--timeout` and `PODSSH_TIMEOUT` on `operator`, `proxy` and `pipe`
  (T-613).
- A copy to a node races the roads that `podssh ssh` races (T-551); the
  quick tunnel's node takes its net's members as its door (T-550);
  OpenTunnel's road at the node and the client (T-530, T-531).
- A client's lost link during a node's bulk costs the node's other sessions
  no backoff (T-421).

Relay selection:

- `podssh relay rank` measures each relay host from this host and keeps the
  rank (T-606); the default list takes it, with the samples of each race
  (T-607); `RelayRank auto` ranks in a session's background, at most once a
  day for each egress (T-608, Q89); `relay info` says that the pool's order
  is the relay's (T-610, GitHub #125).

Repairs:

- An ECDSA key of P-256 whose scalar OpenSSH writes in 31 bytes is read
  (T-609); a roost on a host with no sshd says so, and `doctor` has a line
  for a roost (T-590, GitHub #116); `doctor`'s diagnosis of the TLS
  handshakes counts the resolvers of DNS over HTTPS and n0's relays
  (T-604); on WARP's road, the end of a stream waits for the bytes that the
  far side has not acknowledged yet, so a large echo no longer stalls
  (T-599).
- `podssh pipe -v` says, for each direction, when its input ended and how
  the other side took the shutdown (T-465).

## Check a download

```sh
T=v1.1.0-beta.2; B=podssh-x86_64-unknown-linux-musl   # or another file of the table
curl -fsSLO "https://github.com/Azathothas/podssh/releases/download/$T/$B"
curl -fsSLO "https://github.com/Azathothas/podssh/releases/download/$T/SHA256SUMS"
grep " $B\$" SHA256SUMS | sha256sum -c - && chmod +x "$B"
./"$B" --version   # podssh 1.1.0-beta.2 (the commit of the tag)
```

`podssh update --version v1.1.0-beta.2` from `v1.1.0-beta.1` or `v1.0.1`
takes it, checked by its signature; a build of a release follows releases
alone, so without `--version` it stays on `v1.0.1`. The provenance and the
signature are checked as for `v1.0.0` ([its notes](https://github.com/Azathothas/podssh/blob/main/docs/releases/v1.0.0.md)),
with `T=v1.1.0-beta.2`.

## How it was checked

By the operator's ruling Q88 (2026-11-03), until podssh is stable: the gate
green at the tag's commit, the release workflow by hand on it, and the short
form of its binary (`scripts/release-short.sh BINARY --net`); after the tag,
`release-proofs.yml` and `update-live.yml`. The whole release check and the
live runs of each road wait until then.

## What a beta does not have yet

- The whole check of a release from end to end with no human
  (`scripts/release-check.sh`, T-251): it waits (Q88).
- Signatures of the platforms: the Mac binaries are not signed with an
  Apple Developer ID, and the Windows binaries carry no Authenticode
  signature, so SmartScreen may warn. The proofs above stand in for them.

## Report a defect

Open an issue at <https://github.com/Azathothas/podssh/issues> with the
output of `podssh --version` and `podssh doctor --json`. Read that output
before you post it: it names this host's proxy and addresses, and never a
token or a password.
