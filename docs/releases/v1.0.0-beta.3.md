# podssh v1.0.0-beta.3

The third beta. It carries the repairs since `v1.0.0-beta.2`, the iroh road
and WARP's road in each binary, the DERP road, and `podssh update`, which
replaces the binary with a signed release. A beta is a prerelease. Its tag never moves: a defect found in it
goes into the next beta.

## The files

| File | For |
| --- | --- |
| `podssh-x86_64-unknown-linux-musl` | Linux on x86-64, static: no library and no loader needed |
| `podssh-aarch64-unknown-linux-musl` | Linux on aarch64, static |
| `podssh-armv7-unknown-linux-musleabihf` | Linux on 32-bit ARM with hard float (a Raspberry Pi with a 32-bit system), static |
| `podssh-riscv64gc-unknown-linux-musl` | Linux on 64-bit RISC-V, static |
| `podssh-aarch64-apple-darwin` | macOS on Apple silicon; it links the system's libraries only |
| `podssh-x86_64-apple-darwin` | macOS on Intel |
| `podssh-x86_64-pc-windows-msvc.exe` | Windows on x86-64, with a static C runtime |
| `podssh-aarch64-pc-windows-msvc.exe` | Windows on ARM64, with a static C runtime |
| `SHA256SUMS` | The SHA-256 of each binary |
| `SHA256SUMS.sigstore.json` | The signature of `SHA256SUMS`: Sigstore's keyless signing, by the release workflow at this tag |
| `provenance.sigstore.json` | The provenance of each binary (SLSA), signed the same way: the workflow, the tag and its commit |
| `THIRD-PARTY-LICENSES.md` | The licenses of the crates in the binaries, with their texts |

Each binary ran on its own platform before it was published: `--version`,
the whole manual, `keygen` and `keygen -y`, the iroh road's parse of a
ticket, WARP's road asking for Cloudflare's Terms before it dials, and
GitHub's SSH banner through the live relay.

## Check a download

```sh
T=v1.0.0-beta.3; B=podssh-x86_64-unknown-linux-musl   # or another file of the table
curl -fsSLO "https://github.com/Azathothas/podssh/releases/download/$T/$B"
curl -fsSLO "https://github.com/Azathothas/podssh/releases/download/$T/SHA256SUMS"
grep " $B\$" SHA256SUMS | sha256sum -c - && chmod +x "$B"
./"$B" --version   # podssh 1.0.0-beta.3 (the commit of the tag)
./"$B" doctor      # what this host allows, and whether the whole path works
```

On macOS, check with `shasum -a 256 -c` in place of `sha256sum -c -`. A
binary that `curl` fetched has no quarantine; after a browser's download,
run `xattr -d com.apple.quarantine "$B"` first. On Windows, compare
`(Get-FileHash podssh-x86_64-pc-windows-msvc.exe).Hash` with its line in
`SHA256SUMS` (the case of the letters differs).

The provenance of a binary names the release workflow and the tag (with the
GitHub CLI):

```sh
gh attestation verify "$B" --repo Azathothas/podssh \
  --signer-workflow Azathothas/podssh/.github/workflows/release.yml --source-ref "refs/tags/$T"
```

The signature of `SHA256SUMS` names the workflow at the tag (with cosign; 3.x
and 2.6 both check it):

```sh
curl -fsSLO "https://github.com/Azathothas/podssh/releases/download/$T/SHA256SUMS.sigstore.json"
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Azathothas/podssh/.github/workflows/release.yml@refs/tags/$T" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
```

The two proofs and `podssh --version` name the same commit.

## What works

`podssh ssh`, `each`, `run`, `job`, `session`, `containers`, `proxy`, `pipe`,
`cp`, `mv`, `scp`, `sftp` and `edit`, `doctor`, `keygen`, `agent`, `man`,
`status`, `ping`, `health`, `node`, `operator`, `relay`, `chat`, `play`,
`config`, `mcp` and `update`. `podssh man` is the reference: each command,
flag, `-o` keyword, variable, file and exit code. The iroh road is in each
binary: `podssh node --iroh`, a destination `iroh:TICKET`, and
`--iroh-ticket`. So is WARP's road, `warp://HOST[:PORT]`, and the DERP road,
`podssh node --derp` and a destination `derp:TICKET`. These binaries have no
Tailscale: `podssh ts` exits with 70 and says so.

## What to test again

New since `v1.0.0-beta.2`:

- `podssh update`: the newest release for this binary's own target. Its
  `SHA256SUMS` is checked against Sigstore's signature by this repository's
  release workflow at the tag, then the binary's own sum, before the binary
  is replaced in place. `--check` only looks; `--version TAG` takes a given
  release (T-375).
- The iroh road in each binary, and a notice when a relay refuses this
  binary's iroh, which names `podssh update` and `--iroh-relay` (T-348). The
  road keeps UDP only once a datagram came back, so a host that drops UDP
  goes through the relay at once (#70, T-359).
- `warp://HOST[:PORT]` with `ssh`, `-J` and `proxy`: a port of any host
  inside Cloudflare WARP's tunnel, MASQUE over HTTP/2 on port 443 through
  the proxy, with no relay. The first run registers one device, only once
  `PODSSH_WARP_ACCEPT_TERMS=yes` accepts Cloudflare's Terms, and keeps its
  record in the cache. A proxy that allows names alone refuses the
  endpoint's address, and podssh says so (#63, T-352).
- `podssh node --quick-tunnel` reaches the quick tunnel's edge inside WARP's
  tunnel when port 7844 is closed to the host, or first with `--warp`
  (T-374).
- The DERP road: `podssh node --derp` serves a node through Tailscale's
  public DERP servers (or those of `--derp-server`), and `podssh ssh
  derp:TICKET` reaches it. A node with an allowlist and no pair serves it
  unasked; `PODSSH_DERP=no` turns that off. `node://NAME --derp-ticket`
  adds it to the race of a node's roads, and `podssh doctor` has a section
  `derp` (T-379).
- When no relay host opens a session and no relay was named, `podssh ssh`
  and the commands that reach a server as it does try the direct road once,
  through the proxy, and say so; `PODSSH_DIRECT=no` turns that off (T-363).
- `--forwarder TEMPLATES`: other products' WebSocket forwarders in place of
  the relay, such as Mudlet's or ssheasy's, for `ssh`, `proxy` and the
  commands of `ssh`'s road; `PODSSH_FORWARDER` and the settings file's
  `Forwarder` give them too, and `podssh doctor --forwarder` checks them
  (#59, T-369).
- `-J USER@HOST:443` through a proxy that allows port 443 alone, with the
  hop's password from `SSH_ASKPASS`, and `podssh doctor --hop`, which says
  whether a hop answers with SSH there (#61, T-371).
- The iroh road keeps a signed record of its node's home relay at n0's
  pkarr server, so a client whose ticket names an old relay finds the node;
  `PODSSH_IROH_PKARR=off` turns it off (T-350).
- `podssh pipe http-listen:PORT relay:%h:%p`: an HTTP CONNECT proxy for a
  program that knows only `HTTPS_PROXY`, with `--proxy-auth-file` for an
  address off loopback (#75, T-367).
- `podssh pipe` with `ws://`, `wss://` and `ws-listen:`: a WebSocket by its
  URL, and a WebSocket server in front of a port (#76, T-368).
- `podssh ssh iap://` and `eice://`: the tunnels of Google Cloud's IAP and of
  AWS's EC2 Instance Connect Endpoint. Their tokens and credentials come
  from files, never from the command line (T-351). They were built against
  stand-ins; a live report is welcome.
- `-R` takes each form of OpenSSH's: socket paths on either side, and the
  remote SOCKS form (#73, T-365).
- `-J cf://HOST`: a Cloudflare tunnel as the first hop of a jump chain
  (T-347).
- `podssh doctor`:
  - whether the proxy takes an address as well as names (#74, T-366);
  - the listeners that this host allows, each listened on once (T-357,
    T-358);
  - this host's clock, when a certificate looks expired or not yet valid,
    in each command's TLS failure too (T-345);
  - the system's stores of roots on Windows and macOS, and what to do about
    an issuer that no root signs (T-340).
- DNS over HTTPS in RFC 8484's wire form, with Quad9 after Cloudflare and
  Google. The addresses that carried a session are tried when the resolvers
  fail (T-344).
- The quick tunnel over QUIC, where UDP reaches Cloudflare's edge (T-301).
- russh 0.65.0, with its security fixes (T-356); the keys of the AEAD
  ciphers are wiped when a cipher is dropped (T-377).

## What a beta does not have yet

- The check of a release from end to end with no human (T-251); it runs
  before `v1.0.0`.
- Signatures of the platforms: the Mac binaries are not signed with an
  Apple Developer ID, and the Windows binaries carry no Authenticode
  signature, so SmartScreen may warn. The proofs above stand in for them.

## Report a defect

Open an issue at <https://github.com/Azathothas/podssh/issues> with the
output of `podssh --version` and `podssh doctor --json`. Read that output
before you post it: it names this host's proxy and addresses, and never a
token or a password.
