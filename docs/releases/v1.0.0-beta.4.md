# podssh v1.0.0-beta.4

The fourth beta. It carries the repairs since `v1.0.0-beta.3`: a run in the
background that podssh starts again and watches, and that leaves a login
session's scope of systemd, a node that goes on past its pair's expiry, a
quick tunnel that races its roads, keeps two connections and rides out the
edge's GOAWAY, and the repairs of a bulk session through a node. A beta is a prerelease. Its tag never moves: a defect found in it
goes into the next beta.

## The files

| File | For |
| --- | --- |
| `podssh-x86_64-unknown-linux-musl` | Linux on x86-64, static: no library and no loader needed |
| `podssh-aarch64-unknown-linux-musl` | Linux on aarch64, static |

| `podssh-aarch64-pc-windows-msvc.exe` | Windows on ARM64, with a static C runtime |
| `SHA256SUMS` | The SHA-256 of each binary |
| `SHA256SUMS.sigstore.json` | The signature of `SHA256SUMS`: Sigstore's keyless signing, by the release workflow at this tag |

| `THIRD-PARTY-LICENSES.md` | The licenses of the crates in the binaries, with their texts |

Each binary ran on its own platform before it was published: `--version`,
the whole manual, `keygen` and `keygen -y`, the iroh road's parse of a
ticket, WARP's road asking for Cloudflare's Terms before it dials, and
GitHub's SSH banner through the live relay.

## Check a download

```sh
T=v1.0.0-beta.4; B=podssh-x86_64-unknown-linux-musl   # or another file of the table
curl -fsSLO "https://github.com/Azathothas/podssh/releases/download/$T/$B"
curl -fsSLO "https://github.com/Azathothas/podssh/releases/download/$T/SHA256SUMS"
grep " $B\$" SHA256SUMS | sha256sum -c - && chmod +x "$B"
./"$B" --version   # podssh 1.0.0-beta.4 (the commit of the tag)
./"$B" doctor      # what this host allows, and whether the whole path works
```

On macOS, check with `shasum -a 256 -c` in place of `sha256sum -c -`. A
binary that `curl` fetched has no quarantine; after a browser's download,
run `xattr -d com.apple.quarantine "$B"` first. On Windows, compare
`(Get-FileHash podssh-x86_64-pc-windows-msvc.exe).Hash` with its line in
`SHA256SUMS` (the case of the letters differs).

The provenance of a binary names the release workflow and the tag (with the
GitHub CLI):

```sh
gh attestation verify "$B" --repo Azathothas/podssh \
  --signer-workflow Azathothas/podssh/.github/workflows/release.yml --source-ref "refs/tags/$T"
```

The signature of `SHA256SUMS` names the workflow at the tag (with cosign; 3.x
and 2.6 both check it):

```sh
curl -fsSLO "https://github.com/Azathothas/podssh/releases/download/$T/SHA256SUMS.sigstore.json"
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Azathothas/podssh/.github/workflows/release.yml@refs/tags/$T" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
```

The two proofs and `podssh --version` name the same commit.

## What works

`podssh ssh`, `each`, `run`, `job`, `session`, `containers`, `proxy`, `pipe`,
`cp`, `mv`, `scp`, `sftp` and `edit`, `doctor`, `keygen`, `agent`, `man`,
`status`, `ping`, `health`, `node`, `operator`, `relay`, `chat`, `play`,
`config`, `mcp`, `update` and `detached`. `podssh man` is the reference: each command,
flag, `-o` keyword, variable, file and exit code. The iroh road is in each
binary: `podssh node --iroh`, a destination `iroh:TICKET`, and
`--iroh-ticket`. So is WARP's road, `warp://HOST[:PORT]`, and the DERP road,
`podssh node --derp` and a destination `derp:TICKET`. These binaries have no
Tailscale: `podssh ts` exits with 70 and says so.

## What to test again

New since `v1.0.0-beta.3`:

- `--detach` (`-f` for `ssh`): a run that podssh sends into the background
  itself, once it is online, with its log in the cache (T-380); with
  `--restart`, a small supervisor starts it again whenever it ends, never
  giving up, and starts it again when it hangs: each run beats a file each
  10 s, and one silent for 90 s is ended and started again (T-390, T-394).
  `--detach-name NAME` and `podssh detached list`, `status NAME` and `stop
  NAME`: a second start of a name that runs is refused (T-392). A run with no
  `/dev/null` uses closed pipes, the log is cut with no line lost, old files
  go, and the run leaves the caller's working directory (T-397). A line that
  fails to write (a full disk, a closed journal) no longer ends a run (T-389).
  On Linux, a run detached from a login session asks the user's systemd for
  a scope of its own, `podssh-detached-PID.scope`, as tmux does, so that a
  logout does not end it where logind ends a session's processes; its log
  says the outcome, and `PODSSH_SYSTEMD=no` asks nothing (T-381).
- `podssh ssh --persist-forever`: connect again after each loss with no limit
  (T-391); `podssh ssh --install NAME -N -R ... --persist`: a reverse tunnel as
  a service of this user (T-393). `--install` services restart after each end,
  with a cron watchdog, a LaunchAgent on macOS and a task on Windows (T-393).
- `podssh update` runs the new binary once before it takes the old one's
  place, keeps the old one as `podssh.prev`, and `--rollback` puts it back
  (T-396).
- A node says its pair's expiry 24 h, 6 h and 1 h before it, with the command
  that makes the next pair; `podssh relay pair NAME` makes it in the last day
  of the old one, and the node takes it at the expiry with no new start;
  `podssh status` names each stored pair's expiry (T-395). A node closed by
  the relay for a fault connects again (T-409), and a bulk session through a
  node moves with no fault (T-410). A node that starts while the relay still
  holds the socket of the pair's last node (a restart, a script that starts
  the next one at once) connects again for 30 s instead of exiting at the
  relay's 409 (T-416).
- The quick tunnel (`podssh node --quick-tunnel`): its roads (QUIC, HTTP/2,
  HTTP/2 inside WARP) race with a stagger of 2 s, QUIC after a probe of UDP of
  300 ms (T-400); on the edge's GOAWAY its visitors go on for up to 90 s while
  a new connection takes the new ones (T-402); a window of small frames left
  unread no longer ends the connection (T-408); a push of configuration is
  answered over HTTP/2 and QUIC (T-404, T-411); a refusal of
  `api.trycloudflare.com` for now is asked again after its Retry-After (T-401).
  The node keeps two connections to the edge, the second to its other region,
  so that a region in trouble leaves one standing (T-414).
- WARP's tunnel under volume (T-398), and a front door's new key read from the
  device's record (T-399); a front door that shows another certificate once
  is asked once more a second later before the road gives up (T-419).
- `pipe` and `proxy` write what their source has ready together, up to
  32 KiB, so that a source of small reads no longer pays a write for each.
  Through Tor (a build with the feature `tor`) that took the download from
  2.9 to 7.8 MiB/s through a private network; the Tor road also runs on two
  threads, and it is measured on Tor's public network (T-353).
- DNS over HTTPS through a proxy asks each resolver by its name first (T-405),
  and over HTTP/2 it ends each connection with GOAWAY (T-418).
- `ssh+tls://`, SSH inside TLS as a hop or the destination (#61, T-372); a
  Shadowsocks road from a file of `ss://` lines that a subscription can
  refresh (#62, T-373); meek and WebTunnel inside the Tor road's process, in a
  build with the feature `tor` (T-385).
- `cp` of many small files: the far digest's command starts beside each
  file's sync and close, and a tree of 50 files or more that go one at a
  time says once that `--parallel 8` copies 8 at once (T-417).

## What a beta does not have yet

- The whole check of a release from end to end with no human
  (`scripts/release-check.sh`, T-251): its parts ran on this beta's way; the
  whole run, before the tag and after it, is `v1.0.0`'s.
- Signatures of the platforms: the Mac binaries are not signed with an
  Apple Developer ID, and the Windows binaries carry no Authenticode
  signature, so SmartScreen may warn. The proofs above stand in for them.

## Report a defect

Open an issue at <https://github.com/Azathothas/podssh/issues> with the
output of `podssh --version` and `podssh doctor --json`. Read that output
before you post it: it names this host's proxy and addresses, and never a
token or a password.
