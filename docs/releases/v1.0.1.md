# podssh v1.0.1

The repairs of the defects that the testers of `v1.0.0` found (GitHub #83 to
#111, and the report of the operator's testing agents of 2026-11-02), with the
work of milestone M10 that `main` holds since `v1.0.0`: podssh's own relay
role, the net of an owner's nodes, and more roads. Its tag never moves: a
defect found in it goes into the next release.

## The repairs

- SSH to a server of Go's x/crypto/ssh: a reply to a keepalive or to `-R`
  that carries data no longer ends the connection (T-460, #83, #85).
- `podssh ssh` exits 255, not the far command's status, when the link ends
  after the status and before the output's end (T-461, #84).
- A `-J` hop whose channel opens and carries nothing is named, within
  ConnectTimeout (T-462, #86).
- A connection that ends right after the login is no longer read as a
  refused session; a refusal gives OpenSSH's words of its reason (T-464,
  #104).
- `sftp`'s `ls` gives OpenSSH's long form, and its switches act (T-471, #89).
- `cp --delta` says why it sends a whole file, and makes the temporary file
  by one command where the server has no `copy-data` (T-470, #87).
- `cp -r` says each failure once, and a device, FIFO or socket is a skip with
  exit 0, not 66 (T-476, #105).
- `health` gives a container's CPUs and memory from its cgroup beside the
  host's (T-480, #88).
- The login name comes from the user database when `USER`, `LOGNAME` and
  `USERNAME` are unset (T-500).
- `--su` ends su's read when its password cannot be given (T-501).
- `-o ProxyCommand=none` goes past a file's `ProxyCommand`, and the first
  value of a file holds (T-502).
- Each host that is dialed, `-J`'s hops among them, is checked before
  anything connects, on each road (T-503).
- `each` refuses a blank that would part two hosts of the command line (T-504).
- The keywords of a restriction (`Ciphers`, `MACs`, `KexAlgorithms`,
  `HostKeyAlgorithms`, `PubkeyAcceptedAlgorithms`, `CASignatureAlgorithms`,
  `RequiredRSASize`) apply (T-505).
- `session list` and `detached list` say on stderr that none is there, and
  take `--json` (T-506).
- `update` names the move of the kept file as the way back, and `--rollback`
  only for a release that has it (T-507).
- The fallback to other products' forwarders follows only a failure where no
  relay host answered about the target (T-509, #106).
- The relay's record keeps a host that opens, rests one cut short twice, and
  keeps each road apart (T-563, #110).
- WARP's road proves a packet through its tunnel before it is open (T-560,
  #107).
- A warning before the relay's idle cut, and `--idle-warn SECONDS` (T-463,
  #98).

## Check a download

```sh
T=v1.0.1; B=podssh-x86_64-unknown-linux-musl   # or another file of the table
curl -fsSLO "https://github.com/Azathothas/podssh/releases/download/$T/$B"
curl -fsSLO "https://github.com/Azathothas/podssh/releases/download/$T/SHA256SUMS"
grep " $B\$" SHA256SUMS | sha256sum -c - && chmod +x "$B"
./"$B" --version   # podssh 1.0.1 (the commit of the tag)
```

`podssh update` from `v1.0.0` takes it, checked by its signature. The
provenance and the signature are checked as for `v1.0.0`
([its notes](https://github.com/Azathothas/podssh/blob/main/docs/releases/v1.0.0.md)),
with `T=v1.0.1`.

## How it was checked

As `v1.0.0`: the release check of T-251 (`scripts/release-check.sh`) ran before the tag on the
release's dry run and a build of its own, and runs again on the published files, the checksums,
the signature of `SHA256SUMS` and the provenance of each binary first; then the README's first
steps, `doctor`, `proxy` and `ssh` through the live relay, the reverse road with two sessions at
once, `cp` of 200 MiB each way through a node, `pipe`, the iroh road through n0's relays, the
static binary in a fresh container and in a box like the target sandbox, the Tailscale runs
against headscale, the throughput run, IRC against ngircd, and the planted defect of each check.
GitHub's runners ran the rest: Windows and macOS, the box, WARP's road, Cloudflare's edge, the
public forwarders, DNS over HTTPS, a node as a unit of systemd, `podssh update`, 200 MiB each way
through a node with its moves, and the servers of the repairs: Go's x/crypto/ssh, wstunnel, the
`via` forwarders, and containers of cgroup limits for `health`. `docs/STATUS.md`, "The release
check", holds the table of each run.

## What is not in it

As in `v1.0.0`: the entries that wait for the relay's operator, the work that
the operator holds (Q32), the imports of T-328, the live runs of T-376, the
outside services that turn the relay's address away, the platforms'
signatures, and Tailscale and the Tor road, which need their features.

## Report a defect

Open an issue at <https://github.com/Azathothas/podssh/issues> with the
output of `podssh --version` and `podssh doctor --json`. Read that output
before you post it: it names this host's proxy and addresses, and never a
token or a password.
