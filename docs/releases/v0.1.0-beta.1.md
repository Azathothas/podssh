The first public beta of podssh: SSH from machines whose only way out is
HTTPS.

## What works

- **`podssh ssh`**: an SSH client that needs no installed `ssh`. It reaches
  the server through the WebSocket relay (directly or through
  `HTTPS_PROXY`), or with `--direct` over TCP. It takes the command line of
  OpenSSH: `-p`, `-l`, `-i`, `-J`, `-W`, `-N`, `-n`, `-s`, `-t`, `-tt`, `-T`,
  `-e`, `-C`, `-q`, `-v`, `-E`, `-V`, `-4`, `-6`, and `-o` with the common
  options. It checks host keys against `known_hosts` (hashed entries,
  wildcards, `@revoked`). Keys come from an agent or key files (Ed25519,
  ECDSA, RSA with SHA-2). Passwords, passphrases and keyboard-interactive
  answers come from the terminal or `SSH_ASKPASS`. Keepalives are on. The
  exit codes are those of OpenSSH; a remote command stopped by a signal
  exits 128 plus the signal number.
- **`podssh proxy HOST PORT`**: a byte pipe through the relay, for the
  `ProxyCommand` of OpenSSH or for another TCP protocol.
- **`podssh doctor`**: what the host allows (user database entry, pty,
  socket binds, which directories run programs, `/proc`, where host keys and
  tokens can be written), and whether the full path works (the proxy and
  what it allows, DNS and DNS over HTTPS, each relay host, a token, a
  forward session to `github.com:22` identified by GitHub's published host
  key, the clock). One `ok`, `FAIL` or `????` line for each check; exit 1
  only when a check failed.
- **`podssh keygen`**: Ed25519, ECDSA and RSA keys in the format of OpenSSH,
  for hosts with no working `ssh-keygen`, and `-y` and `-l`. It asks for a
  passphrase and never takes one from the command line.

## Made to depend on no single part

- **Relay failover.** podssh tries the main relay host and up to three
  hosts of its pool, each for 45 s or less. `--relay-host` takes an ordered
  list. A token is cached, and minted again when the relay refuses it.
- **No proxy, no DNS.** Through a proxy, podssh sends names and needs no
  DNS. With no proxy, it uses pinned addresses (`--relay-addr HOST=IP`),
  then the system resolver, then DNS over HTTPS to Cloudflare and Google by
  IP literal.
- **Liveness.** The session pings the relay and declares a silent link dead
  in 30 to 40 s. It does not wait forever.
- **Trust.** TLS is always verified: against an explicit `--ca-file`, or
  against the system bundle and the Mozilla roots in the binary.

## Tests

- In the release gate, against OpenSSH and Dropbear servers, 98 checks:
  exit statuses and signals, payload digests, each authentication method,
  host-key refusals, `-W`, `-J`, subsystems, interactive ptys with resize,
  Ctrl-C, `vi`, `less` and `top`; each key of `podssh keygen` read by the
  `ssh-keygen` of OpenSSH and accepted by `sshd`; and a stand-in relay and
  proxy that fail on purpose (a host down, a 503, a silent host, no TLS, a
  proxy's 502, a Close during a transfer, the byte limit, a stall, a host
  that stops during a session).
- Interactive use on Windows in a real pseudo console (ConPTY): window
  size, resize, Ctrl-C, `vi`, `less`, `top`, `~.`, and the console restored.
- Through the live relay, directly and through a CONNECT proxy that allows
  only port 443.
- In a Podman box built to the measured profile of the target sandbox (no
  route out except a CONNECT proxy, no DNS, no capabilities, `bind` and UDP
  refused, no pty, no user database entry): `doctor`, `proxy`, `keygen` and
  `ssh` pass.
- In the real constrained sandbox that podssh is made for: **not yet**. It
  is the last check before this release. Update this line with its result.

## Binaries

| File | For |
| --- | --- |
| `podssh-x86_64-unknown-linux-musl` | Linux x86_64, static (no libc, no interpreter) |
| `podssh-aarch64-unknown-linux-musl` | Linux arm64, static |
| `podssh-x86_64-pc-windows-msvc.exe` | Windows x86_64, no C runtime DLL |

`SHA256SUMS` holds their SHA-256 sums.

```sh
curl -fsSLo podssh https://github.com/Azathothas/podssh/releases/download/v0.1.0-beta.1/podssh-x86_64-unknown-linux-musl
chmod +x podssh
./podssh doctor
./podssh ssh user@example.org
```

## Known limitations

- No `-L`, `-D` or `-R` forwarding (podssh never listens; use `-W`), no
  agent forwarding, no X11.
- podssh does not read `ssh_config` files yet (`-F none` only). Give options
  with `-o`.
- Host certificates are checked as plain keys; `@cert-authority` is not used.
- A dropped connection ends the session. Sessions that survive a drop come
  in a later milestone.
- The limits of the relay apply: an idle cut at 180 s (podssh's keepalives
  prevent it), and 12 h and 64 MiB for each session.

Reverse mode, `podssh serve`, file copy and chat come in later milestones
(`docs/ROADMAP.md`).
