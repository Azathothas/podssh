The first public beta of podssh: SSH from machines whose only way out is
HTTPS.

## What works

- **`podssh ssh`**: a native SSH client that needs no installed `ssh`. It
  reaches the server through the WebSocket relay (directly or through
  `HTTPS_PROXY`), or with `--direct` over TCP. OpenSSH's command line: `-p`,
  `-l`, `-i`, `-J`, `-W`, `-N`, `-n`, `-s`, `-t`/`-tt`/`-T`, `-e`, `-C`, `-q`,
  `-v`, `-E`, `-V`, `-4`/`-6` and `-o` with the common options. Host keys are
  checked against `known_hosts` (hashed entries, wildcards, `@revoked`); keys
  come from an agent or key files (Ed25519, ECDSA, RSA with SHA-2); passwords,
  passphrases and keyboard-interactive answers come from the terminal or
  `SSH_ASKPASS`. Keepalives are on by default. Exit codes follow OpenSSH, and a
  remote command killed by a signal exits 128 + the signal number.
- **`podssh proxy HOST PORT`**: a byte pipe through the relay, for OpenSSH's
  `ProxyCommand` or any TCP protocol.
- **`podssh doctor`**: what the host allows (user database entry, pty,
  binding sockets, which directories can run programs, `/proc`, where host
  keys and tokens can be written) and whether the whole path works (the
  proxy and what it lets through, DNS and DNS over HTTPS, each relay host,
  a token, a forward session to `github.com:22` identified by GitHub's
  published host key, the clock). One `ok`, `FAIL` or `????` line per
  check; exit 1 only when a check failed.
- **`podssh keygen`**: Ed25519, ECDSA and RSA keys in OpenSSH's format for
  hosts without a working `ssh-keygen`, plus `-y` and `-l`. A passphrase is
  asked for and never taken from the command line.

## Built not to depend on any one thing

- **Relay failover.** By default podssh tries the relay's main host and up to
  three hosts from its pool, each bounded at 45 s; `--relay-host` takes an
  ordered list. A token is cached and re-minted when the relay rejects it.
- **No proxy, no DNS.** Through a proxy podssh sends names and needs no DNS.
  Without one it uses `--relay-addr HOST=IP` pins, then the system resolver,
  then DNS over HTTPS to Cloudflare and Google by IP literal.
- **Liveness.** The session pings the relay and declares a silent link dead
  in 30 to 40 s instead of hanging.
- **Trust.** TLS is always verified, against an explicit `--ca-file`, or the
  system bundle plus the Mozilla roots compiled into the binary.

## Tested

- Against OpenSSH and Dropbear servers in the release gate, 98 checks: exit
  statuses and signals, payload digests, every authentication method,
  host-key refusals, `-W`, `-J`, subsystems, interactive ptys with resize,
  Ctrl-C, `vi`, `less` and `top`; every key `podssh keygen` makes read by
  OpenSSH's own `ssh-keygen` and accepted by `sshd`; and a stand-in relay and
  proxy failing on purpose (a host down, 503, silent, no TLS, a proxy's 502,
  a Close mid-transfer, the byte cap, a stall, a host killed mid-session).
- Interactive use on Windows in a real pseudo console (ConPTY): window size,
  resize, Ctrl-C, `vi`, `less`, `top`, `~.`, and the console restored.
- Through the live relay, directly and through a CONNECT proxy that allows
  only port 443.
- From the constrained sandbox podssh is designed for: **not yet**. It is the
  last check before this release; update this line with its result.

## Binaries

| file | for |
| --- | --- |
| `podssh-x86_64-unknown-linux-musl` | Linux x86_64, static (no libc, no interpreter) |
| `podssh-aarch64-unknown-linux-musl` | Linux arm64, static |
| `podssh-x86_64-pc-windows-msvc.exe` | Windows x86_64, no C runtime DLL |

`SHA256SUMS` holds their SHA-256 sums.

```sh
curl -fsSLo podssh https://github.com/Azathothas/podssh/releases/download/v0.1.0-beta.1/podssh-x86_64-unknown-linux-musl
chmod +x podssh
./podssh doctor
./podssh ssh user@example.org
```

## Known limitations

- No `-L`, `-D` or `-R` forwarding (podssh never listens; `-W` is the
  alternative), no agent forwarding, no X11.
- `ssh_config` files are not read yet (`-F none` only); pass options with `-o`.
- Host certificates are checked as plain keys; `@cert-authority` is not used.
- A dropped connection ends the session; sessions that survive drops are a
  later milestone.
- The relay's limits apply: 180 s idle (podssh's keepalives cover it), 12 h
  and 64 MiB per session.

Reverse mode, `podssh serve`, file copy and chat are later milestones
(`docs/ROADMAP.md`).
