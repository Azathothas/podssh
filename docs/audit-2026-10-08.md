# Code audit, 2026-10-08

A read-only review of every crate, done when the project was taken over after
a previous agent's sessions. It is a **dated snapshot**: file and line numbers
refer to the code as it stood before the rescue (that history was not
published) and drift as the code changes. Fix items here, then delete them;
[STATUS.md](STATUS.md) carries the current summary.
Rows marked **fixed (M1)** were fixed later on 2026-10-08 by milestone 1.

Severity: **high** = breaks a real session or is a security problem; **med** =
wrong behaviour in a reachable case; **low** = cosmetic or latent.

The pattern across the code base: thorough unit tests that check the code
against **itself**. Several tests construct their inputs the same wrong way as
the code they test, so a green suite proved little. Every protocol layer needs
tests against a real peer (OpenSSH/Dropbear sshd, a real ircd, the live relay)
before it is trusted.

## podssh-ws — TLS and WebSocket client

Sound: rustls with podssh's own pure-Rust `CryptoProvider` (TLS 1.3 only:
AES-128/256-GCM; X25519 and P-256; ECDSA P-256/P-384 and Ed25519 signatures).
AEAD wiring matches rustls's reference provider. Nothing on the `connect` path
bypasses certificate or hostname verification. Client frames are masked with
fresh OS randomness.

| # | where | problem | sev |
| --- | --- | --- | --- |
| W1 | `client.rs:198-227,265` | One mutex guards the TLS stream and is held across `read().await`, so a pending read blocks every send — no full duplex. Fix: split into reader and writer halves. | high; **fixed (M1): read and write halves are locked separately** |
| W2 | `client.rs:23,174,265` | One `timeout` is used for connect, upgrade **and** every idle read. Both examples use 20 s, shorter than the relay's 25 s keepalive, so quiet sessions are torn down by podssh. | high; **fixed (M1): separate connect bound and 90 s idle limit** |
| W3 | `client.rs:147-154` | The TLS handshake has no timeout. | high; **fixed (M1): the handshake is bounded** |
| W4 | `client.rs` | No way to send a WebSocket Close; a received Close is not echoed; `WsError::Closed` is never constructed, so close codes and reasons are lost. | high; **fixed (M1): Close is sent, echoed and parsed** |
| W5 | `client.rs:181-194` | Only the first resolved address is tried, with no timeout. No HTTP proxy support at all (the only egress on the measured target). | high; **fixed (M1): every address is tried; HTTP CONNECT proxies supported** |
| W6 | `tls.rs:20-24,34-63` | Trust comes only from a PEM file path; no system bundle, no embedded roots. `webpki-roots` is used only by tests. | high; **fixed (M1): system bundle and compiled-in roots unless a file is given** |
| W7 | `client.rs:97` | Any `?` in the path is refused, which also blocks the relay's `?family=`, `?dial=lazy`, `?precheck=` knobs. | med |
| W8 | `client.rs:124`; `handshake.rs:157-161` | Errors are `String`s and a non-101 response body is dropped, so "wrong token" and "target not allowed" look the same. | med; **fixed (M1): typed `ConnectError` keeps the status and the relay's reason** |
| W9 | `handshake.rs:36-43` | Path, host and token are not checked for CR/LF (header injection through a user-supplied target). | med; **fixed (M1): target, path and token are validated** |
| W10 | `client.rs:258-263` | Fragmented messages are not reassembled; control frames are not checked for FIN and 125-byte payloads. | med; **partly fixed (M1): messages are reassembled; control-frame limits still unchecked** |
| W11 | `sign.rs:128-136` | A P-256 key without the `0x04` prefix is accepted (non-standard leniency). | low |
| W12 | `sign.rs`, `suites.rs` | No RSA signature verification: a relay certificate chain with an RSA leaf or issuer would fail. | med |
| W13 | `random.rs:21`; `kx.rs:55-63` | `OsRng` panics instead of erroring; the X25519 secret is not actually zeroized. | low |
| W14 | `probe.rs` | `PrintChain`, a verifier that accepts every certificate, is a public library export. Move it into the example that uses it. | med |

Unused: `tokio-tungstenite`, `futures-util`, `rsa`, `chacha20poly1305` (no
suite offers it). Re-implemented: SHA-1 and base64 decoding, though both crates
are already dependencies.

## podssh-transport — relay protocol

Sound: forward-leg framing (bare binary, no id prefix, 262144-byte frames);
node-leg session-id codec; control-message types; the reverse close-code
table.

About 600 of 5,646 source lines are reachable outside tests (`adapt.rs`,
`socket::WsSocket`/`Leg`, `forward::ForwardRunner`).

| # | where | problem | sev |
| --- | --- | --- | --- |
| T1 | `socket.rs:114-118`; `adapt.rs` | `send_text` goes out as a **binary** frame, so the relay reads the node's `{"type":"ready"…}` as an id prefix and closes `1003`. The reverse node leg cannot work live. The test double records every send as binary, which hid this. | high |
| T2 | `socket.rs:143-151` | A Close frame becomes `Unexpected` with code and reason dropped. | high |
| T3 | `socket.rs:123-124`; `forward.rs:55-57` | Zero-length keepalive frames are returned as data. | high; **fixed for `proxy` (M1): the pump skips empty frames** |
| T4 | `forward.rs` | `ForwardRunner` takes `&mut self` for both send and receive: there is no duplex I/O driver. | high; **fixed for `proxy` (M1): the pump runs both directions concurrently** |
| T5 | `socket.rs:171-238,270-313` | The `ready` gate is never enforced; `recv_data` and `recv_control` each consume and reject the other frame type. | high |
| T6 | `dns/**` (2,345 lines) | Not used by any caller, and the DoH stage cannot work: no TLS transport, numeric record types parsed as strings, any `"TC"` key treated as truncated, CNAMEs skipped, cache returns the wrong port, a blocking Condvar wait inside an async fn. The relay resolves targets itself and podssh only needs the relay's own name — usually through a proxy that resolves it. | high; **removed (M3, 2026-10-08): `podssh-ws` resolves the relay's name (pins, the system resolver, then DNS over HTTPS by IP literal)** |
| T7 | `backpressure/**` | Unused; its model (local write completion) says nothing about the relay's queue, and two ledger bugs. Real flow control is SSH channel windows. | med |
| T8 | `error.rs:155,165` | `403` is never retried though re-minting fixes an expired self-minted token; `503` is retried against the contract. | med |
| T9 | `endpoint.rs:38-40` | Host and node name are not validated or escaped (`/`, `?`, `#`, `..`). | med |

Dead: the `Transport` trait (no impls), `target_for`, `hostname/report.rs`,
`backoff.rs`, `socket::{build, http_failure, closed}`. Unused dependencies:
`crc32fast`, `hex`, `rustls-pki-types`.

## podssh-core/ssh — SSH protocol (unwired, partly uncommitted)

Sound: RFC 4251 type codec; exchange-hash input order; KDF letters; the
chacha20-poly1305@openssh.com and aes128-gcm@openssh.com primitive wiring
(tag verified before decryption); ed25519 host-key verification.

Against a stock OpenSSH server a session would fail at the first encrypted
packet, at publickey auth, at channel open, and at pty-req.

| # | where | problem | sev |
| --- | --- | --- | --- |
| S1 | `cipher.rs:152,187`; `packet.rs:99-116` | chacha packets aligned on the whole packet; OpenSSH requires `packet_length % 8 == 0`. | high |
| S2 | `cipher.rs:139,143` | Sequence numbers reset to 0 at NEWKEYS (only strict-kex resets them); no way to set the starting number. | high |
| S3 | `kex.rs:141-149` | Algorithm selection follows the server's order; RFC 4253 §7.1 says the client's. | high |
| S4 | `keys.rs:153,166` | RSA host keys can never verify (the key blob is named `ssh-rsa` even when signing with rsa-sha2-256). | high |
| S5 | `auth.rs:189` | Signed data starts with the raw session id instead of a length-prefixed string. | high |
| S6 | `auth.rs:229-230` | The signature is written as two bare strings instead of one string wrapping algorithm and signature. | high |
| S7 | `channel.rs:172-179` | CHANNEL_OPEN_CONFIRMATION read as five u32s; RFC 4254 has four. | high |
| S8 | `channel.rs:363` | pty-req terminal modes appended raw, not as a length-prefixed string. | high |
| S9 | `channel.rs:280-289` | No WINDOW_ADJUST is ever sent: output stalls after 64 KiB. | high |
| S10 | `packet.rs:168-172` | A zero length field with 4 bytes buffered panics (index out of bounds) — triggerable by the peer. | high |
| S11 | `channel.rs:253,273` | `want_reply` is dropped and there is no SUCCESS/FAILURE reply, so server keepalives go unanswered. | high |
| S12 | `kex.rs:14` | No strict-kex (`kex-strict-c-v00@openssh.com`): no Terrapin (CVE-2023-48795) countermeasure, with a relay in the middle by design. | high |
| S13 | — | No rekeying, no session driver (no KEX_ECDH_INIT/REPLY codec, no DISCONNECT/IGNORE/DEBUG/UNIMPLEMENTED/GLOBAL_REQUEST/EXT_INFO handling). | high |
| S14 | `channel.rs:212,244` | stderr mixed into stdout; recipient channel id never checked. | med |
| S15 | `keys.rs:129` | KDF extension wrong past 64 bytes (latent). | low |
| S16 | `kex.rs:166-167` | A MAC overlap is required even when the cipher is an AEAD. | med |
| S17 | `keys.rs:69-76` | An all-zero X25519 shared secret is accepted. | med |
| S18 | `auth.rs` | ed25519 user keys only; encrypted key files refused; no agent; `userauth_signed` asserts (panics) on other key types. | med |

Unused dependencies in podssh-core: `serde_json`, `hmac`, `chacha20poly1305`,
`p256`, `crc32fast`.

## podssh-core/irc — IRC client (unwired)

Sans-IO and well structured. Talks to a public ircd through the relay's
forward path in **plaintext** (port 6667), so the relay can read chat and
file bytes.

| # | where | problem | sev |
| --- | --- | --- | --- |
| I1 | `cap.rs:128-147,194-200`; `session.rs:331-340` | `CAP END` is sent only after 001, but IRCv3 servers hold registration until `CAP END`: registration hangs. A test asserts the wrong order. | high |
| I2 | `cap.rs` | Requests every offered capability; mishandles `sasl=…` values and multi-line `CAP LS`. | high |
| I3 | `encode.rs:68-90`; `transfer/wire.rs:251-253` | No CR/LF/NUL checks: `send_privmsg("#c", "a\r\nQUIT")` injects a QUIT. | high |
| I4 | `command.rs` | Trailing-form `JOIN :#c` / `NICK :n` and colon-less `PRIVMSG` dropped; CAP nick target unparsed. | high |
| I5 | `session.rs` | Any user's PART forgets the channel; KICK unhandled; each 005 line replaces ISUPPORT; reconnect does not reset state; 433 has no alternate nick. | high |
| I6 | `framing.rs` | Overflow and non-UTF-8 handling lose lines, keep an unbounded buffer, and make a Latin-1 line fatal. | high |
| I7 | `transfer/*` | Chunks exceed 512 bytes once the server adds a prefix; ack index wrong for a short final chunk; never run live. | high |

## podssh-terminal — line discipline (unused)

A clean state machine, but used by nothing.

| # | where | problem | sev |
| --- | --- | --- | --- |
| L1 | `session.rs:79-85,173-216` | **Mode selection is inverted.** When the server grants no pty — the case the crate exists for — every key rings the bell and the session ends. When a pty *is* granted it adds local echo on top of the remote echo. | high |
| L2 | — | No raw mode (no termios / Windows console code anywhere); no window-size query or resize handling. | high |
| L3 | `echo/inspect.rs`, `echo/editing.rs` | The cursor counts bytes, not characters: editing non-ASCII text corrupts the screen. | high |
| L4 | `escape.rs:128-139` | `ESC O x` (F1–F4, application-mode arrows) rings the bell and inserts letters; a lone Escape swallows the next key. | high |
| L5 | `editing.rs`, `passthrough.rs` | Delete/Home/End `~` forms unhandled; Home/End move the buffer cursor but not the screen cursor; passthrough refuses Ctrl-Z/S/Q even with a real remote pty; remote output overwrites the line being edited. | med |

## podssh-ts and the vendored fork

`vendor/tailscale-rs` (upstream `f4781c4`, 14 local patches) adds
DERP-over-WebSocket and a CONNECT-proxy dialer. `podssh ts` joins a tailnet
through Tailscale's default control server; only `--ts-mode relay` sends DERP
through `tcp.ts.relay.ajam.dev`. Auto mode always picks `tcp` (the chain
"probe" only checks that a key exists). Ephemeral nodes are never logged out.
The live two-node acceptance has not run. Since 2026-10-08 the adapter is
behind the `ts` cargo feature.

## podssh-probe

Asserts seven structural facts about a pinned copy of the relay document. No
command uses it, and `scripts/check-relay-spec.py` re-implements the same
check against the live relay.
